# story-time

先用故事勾住人，再讲一个真实存在的知识。故事是钩子，不是包装纸。

## 触发

- 「来点故事」「讲个故事」「来一段」「睡前那个」「再来一个」「换一个」
- 带领域更省事：「来点故事，物理的」「讲个经济学故事」「来个跟代码有关的」
- 带系列：「上次那个系列的下一集」
- 带语言：「用英语讲」「来点日语的故事」

## 铁律

1. **故事在前，知识在后。** 顺序不能反。先让人想知道"然后呢"，再告诉他"为什么会这样"。

2. **故事必须有一下反转。** 反转的那一刻，正好就是知识的核心。没有反转的故事只是场景描写，删掉不影响任何东西——那就是废的。

3. **不许写成催眠曲。** 目标是让人愿意多醒两分钟，不是让人睡着。温吞的氛围描写、无意义的天气和月光，一律删。

4. **解释用大白话。** 不甩术语；非用不可就当场用一句话解释掉。类比必须来自日常物件（锅、门锁、快递、排队），别用「就像薛定谔的猫」这种用一个不懂解释另一个不懂。

5. **系列要串。** 同一族的第 N 篇，开头点明跟前面哪篇是一家，结尾说清"区别在哪"。

6. **不许强行升华。** 结尾不硬拐人生哲理、不硬拐某个固定主题。讲完就讲完。

7. **具体分两种：承重的不能让位，装饰的可以让位但要补回来。**
   - **承重**：反转成立所依赖的数字、机制、因果链。动一个，结论就塌。这类必须写准写实，不许为文采牺牲。
   - **装饰**：时间、地点、人名这类不影响反转的细节。可以为句子好听换掉或省略，但必须挪进文末注释，别丢。
   - **判据**：把这一处改掉，反转还成立吗？成立 → 装饰，可以让；不成立 → 承重，一个数都不许动。
   - 例：「1973 年 6 月 30 日上午十点零八分」可缩成「1973 年夏天」，精确时刻挪注释；但「它比月影慢两百公里每小时」不许模糊成「慢一点点」——整个反转就架在那两百上。

8. **先把错误假设递给读者。** 反转打的是读者心里那个想当然。所以别只写事实，要把「大家都会这么想」的那句话写进去，让读者先点头。错误假设是预埋的靶子，不是失误。

## 流程

### 第 1 步：看看讲过什么

先问用户：之前讲过什么、存哪了。

- 用户说了位置 → 去读，看清讲过哪些题、用过哪些领域、有哪些系列、每个系列接到哪了。
- 用户说没存过 / 不想管 → 凭对话记忆挑题，别撞刚才聊过的话题。
- **没读过已讲过的就选题，等于闭眼抽卡。**

### 第 2 步：选题

- 用户指定了领域 → 就在这个领域里挑一个没讲过的角度。
- 没指定 → 挑一个最近几篇里没出现过的领域。参考：物理、生物、语言、城市史、金融、材料、密码学、农业、地图、音律、算法、医学史、航运、建筑、法医。
- **优先挑"反直觉但能讲清"的题**，不挑"大而重要"的题。人记住的是"哦，原来是这样"，不是"这个很重要"。

### 第 3 步：决定要不要搜

只在以下情况联网：

- 题目本身是"最近的进展"（AI、航天、生物医学这些更新快的领域）
- 用户说了"最新的""最近有什么"
- 具体数字、年份、人名拿不准

**拿不准就搜；搜不了就把数字去掉，改成定性描述。** 宁可少一个精确数字，不给一个错数字。

### 第 4 步：写

长度：故事 300~600 字，解释 300~500 字。

**故事**
1. 一个具体的人或物，一个具体的地方，一个具体的时刻。别写"从前有个王国"。
2. 一个处境，具体到能看见画面。
3. 一下反转——这一下必须是知识的核心机制。
4. 收在反转之后，不加总结。

**解释**
- 一句话说清它是什么。
- 为什么它反直觉 / 为什么大多数人想反了。
- 一个日常类比。
- 一个常见误解——这一条最能证明"真懂了"。

### 第 5 步：小本本卡

解释讲完，最后给一个三行的收尾卡，让人关掉对话还能带走点东西：

```
小本本
· 一句话：这个东西是什么（10~20 字，不用术语）
· 记法：一个能钩住的类比或口诀
· 别记错：最常见的那个误解，一句话否掉
```

三个硬要求：

- **必须能独立看懂**。只看这三行、没看故事，也得明白。
- **不重复解释段原句**。换个说法，尤其"记法"这一行要换一个类比或压成短句。
- **三行总共不超过 80 字**。超了就是没提炼。

### 第 6 步：问要不要存

**默认不保存。** 讲完以后问一句：

> 这篇要存下来吗？存的话放哪个目录？

- 用户说存 → 写到用户指定的位置。一篇一个文件，文件名用「序号-标题.md」，正文含故事、解释、小本本卡。
- 用户不指定位置 → 建议一个默认目录（比如 `~/stories/`），问过再用。
- 用户说不存 / 不回应 → 什么都不写，别自作主张建文件。

存了的话，顺手在那个目录下维护一个 `README.md` 当索引，一行一篇：序号、标题、领域、一句话核心。这样下次选题前一眼能看完。

## 多语言模式

用户要某门外语的故事时，整篇换成目标语言，但**解释段和小本本卡留在用户母语**——不然只剩看懂，学不到东西。

### 先问水平

别问「你什么水平」（多数人答不上，而且自评普遍不准）。直接问一句：

> 你读这门语言大概什么感觉：完全看不懂 / 认得字但组不出句 / 能读短句 / 能读文章？

一句话就能定档。用户懒得说 → 按 A2 开局，讲完末尾加一句「按 A2 的难度写的，太浅或太深说一声」。

### 难度分级

| 水平 | 故事篇幅 | 句长 | 生词 | 处理方式 |
|---|---|---|---|---|
| A1–A2 | 100~150 词 | 每句 ≤ 10 词，主谓宾，只用一个时态 | 0 个新词 | 只用最高频词汇；每段后加一行母语梗概 |
| B1–B2 | 200~350 词 | 每句 ≤ 18 词，可从句 | 最多 5 个 | 全部加母语夹注 |
| C1+ | 350~500 词 | 不限 | 不限制 | 夹注可以省，只点一两处地道表达 |

**生词标注是硬要求。** 超出用户水平的那类词，一律在词后加母语意思，格式 `word（中文意思）`——标的是词义，不是整句翻译。判据很简单：**以他现在的水平读，哪些词会卡住**，卡住的就标。宁多标几个，别让人读着读着断了。

### 硬要求

1. **符合那个语言的真实语感。** 不是英文化的中文。英语就用母语者会写的句子节奏，日语就用日语的语序和省略。
2. **反转必须还在。** 语言换了，结构不能塌。
3. **不生造。** 想不起那个词怎么说，就换一个你确定的说法，别硬凑一个听起来像的词。
4. **冷门语言先报底。** 冰岛语、斯瓦希里语这类，开口前说一句「这门语言的把握有限，写得可能不地道」，别装。
5. **一篇之内统一一种变体。** 用户如果说英语，别在同一篇里混 `colour` 和 `color`——写出来像校对事故。

### 为什么这么做

这不是语言课，是**可理解输入**——用半懂的语言读有意思的内容，比背单词表有效得多。所以宁可故事简单，也别为了炫语法牺牲「想知道后来怎样」的劲头。
